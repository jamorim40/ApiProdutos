Explicação do LoginController
===========================

Este arquivo descreve o funcionamento do LoginController, com foco nas validações e na geração do token JWT.

1) Namespace e imports
----------------------
using System.IdentityModel.Tokens.Jwt;
using System.Security.Claims;
using System.Text;
using CadastroProdutos.Models.Entitys;
using CadastroProdutos.Services;
using Microsoft.AspNetCore.Mvc;
using Microsoft.IdentityModel.Tokens;

- System.IdentityModel.Tokens.Jwt: permite trabalhar com JWT, como criar e escrever tokens.
- System.Security.Claims: usado para criar claims, que são informações incluídas no token.
- System.Text: usado para converter a chave JWT em bytes.
- CadastroProdutos.Models.Entitys: acessa o modelo Login.
- CadastroProdutos.Services: acessa a interface ILoginService.
- Microsoft.AspNetCore.Mvc: permite herdar de ControllerBase e retornar respostas HTTP.
- Microsoft.IdentityModel.Tokens: contém classes para assinatura e validação do token.

2) Classe LoginController
-------------------------
[ApiController]
[Route("api/[controller]")]
public class LoginController : ControllerBase

- [ApiController]: indica que a classe é um controller de API.
- [Route("api/[controller]")]: define a rota da API. Para LoginController, a URL fica em /api/login.
- ControllerBase: fornece suporte para retornar respostas como Ok, BadRequest, Unauthorized.

3) Injeção de dependência
-------------------------
private readonly IConfiguration configuracaoUsuario;
private readonly ILoginService iloginservice;

public LoginController(IConfiguration configuracaoUsuario, ILoginService iloginservice)
{
    this.configuracaoUsuario = configuracaoUsuario;
    this.iloginservice = iloginservice;
}

- IConfiguration: lê configurações do appsettings.json, como a chave JWT.
- ILoginService: é o serviço responsável por verificar se o usuário existe e se a senha está correta.
- A injeção de dependência torna o controller mais limpo e flexível.

4) Método de login
------------------
[HttpPost]
public ActionResult Login(Login login)

- [HttpPost]: indica que este método responde a requisições POST.
- O parâmetro Login login recebe os dados enviados pela requisição, normalmente em JSON.

5) Validação inicial das entradas
---------------------------------
if (string.IsNullOrWhiteSpace(login.Usuario) || string.IsNullOrWhiteSpace(login.Senha))
{
    return BadRequest("Usuário e senha são obrigatórios.");
}

- Aqui é feita a primeira validação.
- string.IsNullOrWhiteSpace verifica se o usuário ou a senha vieram vazios, nulos ou com apenas espaços.
- Se faltar algum dado, o método retorna um erro 400 BadRequest.

6) Validação do usuário no banco
--------------------------------
var usuarioAutenticado = iloginservice.Autenticar(login);
if (usuarioAutenticado is null)
{
    return Unauthorized("Credenciais inválidas.");
}

- O controller chama o serviço ILoginService para verificar se o usuário existe e se a senha bate.
- Se o retorno for null, significa que a autenticação falhou.
- Nesse caso, a API retorna 401 Unauthorized, indicando que as credenciais não são válidas.

7) Leitura da configuração JWT
-----------------------------
var jwtConfig = configuracaoUsuario.GetSection("Jwt");
var chave = jwtConfig["Key"] ?? throw new InvalidOperationException("A chave JWT não foi configurada.");
var key = Encoding.ASCII.GetBytes(chave);

- GetSection("Jwt") busca a seção Jwt no arquivo appsettings.json.
- "Key" é a chave secreta usada para assinar o token.
- Se a chave não estiver configurada, é lançada uma exceção.
- Encoding.ASCII.GetBytes(chave) converte a string da chave para bytes, que o token precisa para criar a assinatura.

8) Criação do token JWT
-----------------------
var tokenHandler = new JwtSecurityTokenHandler();
var descricaoToken = new SecurityTokenDescriptor
{
    Subject = new ClaimsIdentity(new[]
    {
        new Claim(ClaimTypes.Name, usuarioAutenticado.Usuario),
        new Claim(ClaimTypes.Role, usuarioAutenticado.Papel)
    }),
    Expires = DateTime.UtcNow.AddHours(1),
    Issuer = jwtConfig["Issuer"],
    Audience = jwtConfig["Audience"],
    SigningCredentials = new SigningCredentials(new SymmetricSecurityKey(key), SecurityAlgorithms.HmacSha256Signature)
};

- JwtSecurityTokenHandler: responsável por criar o token.
- SecurityTokenDescriptor: descreve as propriedades do token.
- Subject: define as claims do usuário. Aqui são colocadas informações como nome e papel.
- new Claim(ClaimTypes.Name, usuarioAutenticado.Usuario): cria a claim com o nome do usuário.
- new Claim(ClaimTypes.Role, usuarioAutenticado.Papel): cria a claim com o papel/permissão do usuário.
- Expires: define quando o token expira. No exemplo, expira em 1 hora.
- Issuer: define quem emitiu o token.
- Audience: define para quem o token foi emitido.
- SigningCredentials: define como o token será assinado, usando a chave secreta e o algoritmo HMAC SHA-256.

9) Geração do token final
-------------------------
var token = tokenHandler.CreateToken(descricaoToken);
var tokenString = tokenHandler.WriteToken(token);

- CreateToken(descricaoToken) cria o objeto do token com as informações configuradas.
- WriteToken(token) transforma o token em uma string legível, que será enviada ao cliente.

10) Retorno da resposta
-----------------------
return Ok(new { token = tokenString });

- Ok retorna o status HTTP 200.
- O objeto retornado contém o token, que o cliente pode salvar e enviar em futuras requisições.

Resumo
------
O LoginController faz três coisas principais:
1. Valida se o usuário e a senha foram informados.
2. Verifica as credenciais no banco por meio do serviço de login.
3. Gera um token JWT com informações do usuário e o devolve ao cliente.

Esse fluxo é o padrão básico de autenticação com JWT em ASP.NET Core.
